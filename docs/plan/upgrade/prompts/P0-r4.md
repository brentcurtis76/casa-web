## [B1] BLOCKING — a JSON tool can fail and still be treated as clean

`scripts/gates/changed-files-diagnostics.sh:198`, the `["eslint", "deno lint"]` loop:

```js
if (parseErrors.has(t))            { … }
else if (!shapeOk.get(t))          { … }
else if (t === "eslint" && exits[t] > 1) { … }
```

- **`exits["deno lint"]` is never consulted at all.** The value is captured and then
  ignored.
- **ESLint exit `1` with zero diagnostics is accepted.** Only `> 1` fails.

Codex's probes, which I reproduced myself and confirm:

```
deno lint prints {"version":1,"diagnostics":[]} and exits 127
other three tools: valid empty output, exit 0
→ gate exits 0, no FALLO          ← should fail

eslint prints [] and exits 1
other three tools: valid empty output, exit 0
→ gate exits 0, no FALLO          ← should fail
```

Round 2 rejected both of these. Round 3 regressed them. They contradict the remediation
contract already recorded in the ledger: classify on `(exit, validity, count)`, and
"zero diagnostics + the command failed ⇒ tool failure".

**Codex explicitly accepted** the different, inherent limitation for `tsc` and `deno check`:
having no structured output, a tool exiting 0 without doing any work is indistinguishable
from a legitimate clean run. That limitation stands and is documented. It does **not**
license ignoring a captured non-zero exit from a tool that does have structured output.

### The rule to implement

Both JSON tools document an exit convention: **0 = nothing to report, 1 = problems found**,
anything else is a failure of the tool itself (ESLint reserves 2 for a fatal config error;
127 is a missing binary). So a JSON tool has **not** run correctly when any of these holds:

1. its output does not parse; or
2. it parses but has the wrong shape (not an array for ESLint; no `.diagnostics` array for
   `deno lint`); or
3. its exit code is outside `{0, 1}`; or
4. its exit code is `1` — "I found problems" — while **zero** diagnostics were parsed.
   That is self-contradictory and means the output is not trustworthy.

Apply items 3 and 4 to **both** tools, not just ESLint. Exit `0` with zero diagnostics
stays a legitimate clean run — that is what round 3 got right and it must not regress.

Leave the `tsc` / `deno check` branch exactly as it is.
