## [S1] SHOULD-FIX — `selftest.sh` leaks every stub directory

`scripts/gates/selftest.sh:81`:

```bash
dir="$(make_stubs "$with_deno")"
```

Command substitution runs `make_stubs` in a **subshell**, so its `STUBS+=("$dir")` mutates
a copy of the array. The parent's `STUBS` stays empty and the `EXIT` trap removes nothing.

I reproduced it. Before a run: 55 temp directories under the system temp dir. After:
**62** — seven new ones, one per case, each containing the `npx` / `deno` stubs:

```
/var/folders/…/T/tmp.sYDieckJ9n: deno npx
/var/folders/…/T/tmp.djpRnjeyO7: deno npx
/var/folders/…/T/tmp.kH0lOLnMLq: npx          ← case 2, deliberately has no deno stub
…
```

This contradicts both the file's own header comment and round 4's requirement to clean up
every stub directory. Codex flagged the accumulating debris as the one thing that makes P1
harder than it needs to be.

### The fix

Stop returning the directory through stdout. Have `make_stubs` assign to a variable in the
caller's scope — for example set a global (`STUB_DIR`) and have `run_case` read it, or
create the directory in `run_case` and pass it into `make_stubs` as an argument. Any shape
is fine as long as `STUBS` is appended to in the **parent** shell, so the existing `EXIT`
trap actually removes them.

Keep everything else about the file: the seven cases, their descriptions, the one-variable
-per-case isolation, the real `PATH`-without-`deno` for case 2, and the exit-code assertion.
Codex's mutation test proves that design works — do not redesign it.

Do not try to delete the temp directories leaked by earlier runs. They are outside the
repo, the OS clears them, and hunting them with a glob is more dangerous than the debris.
